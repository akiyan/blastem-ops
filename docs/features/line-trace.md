# 走査線単位の VDP 書き込みと割り込みの記録

指定フレームのあいだ、CRAM・VSRAM・VDP レジスタへの書き込みと、割り込みの受付・復帰を、それが効いた VDP のライン位置付きで記録する。行ごとの色やスクロールの切替（ラスター効果）を、画面を見ずに確認できる。

## MCP: `line_trace`

`frame_pause` で止めてから呼ぶ。

| 入力 | 内容 |
|---|---|
| `frames` | 進めるフレーム数。1〜600 |
| `kinds` | `cram`・`vsram`・`reg`・`int` から選ぶ。既定はすべて。`int` は割り込みの受付と、それに対応する RTE |
| `lines` | 応答に含めるイベントのライン範囲（`from`・`to`）。集計は全イベントが対象 |
| `max_events` | 応答に含めるイベント数。既定 2000、最大 20000。全イベントはファイルに残る |

応答:

- `summary.by_kind`: 種類ごとの件数
- `summary.interrupts`: 割り込みレベル（4 が H 割り込み、6 が V 割り込み）ごとの回数、最初と最後のライン、受付から RTE までの 68000 サイクル数の最小・最大・平均
- `summary.write_lines`: 書き込みがあったフレーム・ラインの組の数
- `events`: 各イベントの `frame`、`line`（VDP の vcounter）、`slot`（ライン内の水平位置。hcounter の半分）、`kind`、内容（`address`/`reg`、`value`、`level`、`cycles`）

1ラインは 68000 で約 488 サイクル。割り込み処理の `cycles` がこれを超えると、次のラインの割り込みに間に合わない。

### 例: 選択肢の行だけ色を変える演出

```text
cram address=30 line=35 value=0x0A8E   ← 選択行の開始で色を変更
cram address=30 line=74 value=0x0EEE   ← 選択行の終わりで元に戻す
interrupts.4: count=225 cycles min=270 avg=308 max=812
```

## 本体: v2 `line_trace`

capability は `line_trace`。params は `frames`（1〜600）、`path`（絶対パス。既存ファイルには書かない）、`kinds`（省略可）。完了応答は `advance` の結果に `events`（件数）を加えたもの。ファイルの各行は1イベントの JSON。

- CRAM・VSRAM・レジスタは、VDP が書き込みを反映した時点（FIFO を通った後）のライン・スロットを記録する。CPU が書き込み命令を実行した時点とは、FIFO の待ち分だけずれる
- レジスタの値は、VDP が保持する 8 ビット値（背景色レジスタなどのマスク後）
- 割り込みは 68000 が受け付けた時点、RTE は RTE 命令を実行する直前を記録する。RTE は直前に受け付けた割り込みと対応付け、その間の 68000 サイクル数を `cycles` に入れる。対応する割り込みがない RTE は `level` が null
- RTE の検出のため、68000 の JIT が RTE ごとに観測用の関数を呼ぶ。記録していないときは何もしない

## 制限

- GDB 起動時、CD・32X、threaded video は対象外
- VRAM への書き込み（DMA を含む）は記録しない
- `line` は vcounter の値で、V ブランク中は表示ラインの番号と連続しない
- 新しい CPU コア（`NEW_CORE` ビルド）では RTE を記録しない

## 試験

fixture は C ボタンを押している間、毎ラインの H 割り込みで CRAM の 0 番（表示に使わない色）を書き換える。

- C なしでは、毎フレームのレジスタ書き込み（背景色・割り込み設定）だけが記録される
- C ありでは、200 回以上の H 割り込みが昇順のラインで記録され、CRAM 書き込みは割り込みと同じ数・同じラインにあり、受付から RTE までが 10〜200 サイクルに収まる
- `kinds` の絞り込み、不正な params、既存ファイルの拒否
- MCP では、レベル別の集計、ライン範囲の絞り込みを確認する
