# ホスト音声の録音

通常の MD セッションで MCP の `audio_capture {"frames": 180}` を呼ぶと、停止、録音開始、指定フレームの進行、録音終了を行い、ステレオ 16bit PCM の WAV とメタデータを返す。終了時は停止状態。MCP の audio content に実データを含めるので、一時ディレクトリが削除される前にクライアントが保存できる。既存の手動 WAV 録音とは別のファイルを使う。

## 本体

- capability は `host_audio_capture`
- `audio_start` は絶対パスと 1〜30 秒の上限（`max_seconds`）を受け取り、上限に達したら書込みを止める。`audio_stop` で WAV ヘッダーを確定する
- 未開始の終了と二重開始は拒否する
- 既存 writer の不具合を修正した
  - ヘッダー書込長の誤判定
  - float 出力から録音する際の変換バッファの拡張条件
  - ファイル確定時の seek・write・close の失敗を通知していなかった点

## MCP

フレーム数は 1〜600。進行のキャンセルや失敗時も録音終了を試みる。プロセスを強制終了した場合は WAV の確定を保証しない。raw protocol で開始した録音は呼出側が終了する。

## 保証範囲

- ホストのミキサー出力の観測（`boundary: host_mixer`）。VDP フレームに対応するサンプル区間は保証しない。バッファ遅延があり、同じフレーム数でもサンプル数は変わる
- 無音、切り替わり、波形、聴感の確認に使う。サンプル一致での回帰判定には使わない
- GDB による停止とフレーム制御の併用、threaded video、CD・32X は対象外
- 検証環境は Linux x86_64 の SDL 版。既存 WAV writer はホストの little-endian 配置を前提にしており、big-endian 環境での動作は保証しない

## 試験

- 実際の `wave.c` をコンパイルし、Python 標準の wave でヘッダーとサンプルを確認する。`/dev/full` への書込み失敗も確認する（`tests/test_wave_writer.py`）
- core protocol で、未開始の終了、二重開始、書込先のエラー、1秒の上限と実サンプル数を確認する
- fixture の A 入力で PSG 音を鳴らし、MCP が返す WAV の波形変動、メタデータ、停止状態、60フレームの進行を確認する
