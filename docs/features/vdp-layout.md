# VDP の表示内容をテキストで取得する

停止中の VDP の状態を、画像ではなくテキストで返す。表示レイヤーごとに、どの画面位置にどのタイル・パレットが置かれ、どのスプライトがつながっているかを、画像を見ずに比較・検査できる。

## MCP: `vdp_layout`

`frame_pause` などで止めてから呼ぶ。GDB で停止中でも使える。

| 入力 | 内容 |
|---|---|
| `planes` | `a`・`b`・`window` から選ぶ。既定はすべて |
| `sprites` | スプライトのリンクをたどった一覧を返すか。既定 true |
| `hidden_sprites` | 画面外のスプライトも一覧に含める |
| `rect` | 画面上のセル範囲（`x`・`y`・`width`・`height`）。既定は表示全体 |
| `cells` | 空でないセルごとのオブジェクトも返す |
| `patterns` | タイルのパターンデータの CRC32 をセルとスプライトに付ける |

応答の `layout`:

- `mode`: 表示サイズ（H32/H40、V28/V30）、インターレース、表示有効、シャドウ・ハイライト
- `backdrop`: 背景色のパレット番号と色番号
- `scroll`: 水平（全体・8ライン単位・ライン単位）と垂直（全体・2セル単位）のモード、Plane A/B のスクロール値。値が同じ区間をまとめて返す
- `planes`: 各プレーンの名前表アドレス・大きさ、空でないセル数、パレットごとの数と `grid`
  - `grid` は画面の1行を1文字列にしたもの。各セルは `タイル番号(16進)/パレット`。`*` は優先、`h`・`v` は反転、`.` は空（値0）、`-` はウィンドウとの重なりで表示されない位置
  - 各セルはそのセルの左上の画素でスクロールを計算する。ライン単位の水平スクロールや、8の倍数でないスクロールでは `scroll` も併せて見る
- `sprites`: スプライト表のアドレス、リンクでたどった数、表示中の数、上限（H40 は80、H32 は64）、1ラインの表示数上限（H40 は20、H32 は16）を超えるライン、各スプライトの座標・大きさ・タイル・パレット・優先・反転・リンク順。リンクのループや上限超えは `problems` に入る

`artifact` は、デコードに使った KITVDMP1 ファイル（VRAM・CRAM・VSRAM・レジスタ）。

## 本体: v2 `vdp_dump`

capability は `paused_vdp_dump`。params は `path`（絶対パス。既存ファイルには書かない）。停止中（フレーム制御による停止、または GDB 停止）だけ受け付け、その時点の VRAM・CRAM・VSRAM・レジスタを KITVDMP1 形式で書く。従来の `vramdump` は次のフレーム境界まで待つため、停止中は使えなかった。

## 制限

- Mode 5（メガドライブの通常モード）だけを対象にする
- スプライトの Y 座標・サイズ・リンクは VRAM 上の表から読む。実機の VDP 内部キャッシュとは、表のアドレスを変えた直後などに一致しないことがある
- インターレースモード 2 の縦方向の倍解像度は考慮しない
- ライン単位の表示数上限は、表示中のスプライトの縦範囲から数える。ドット数の上限（H40 は 320 ドット）や、X=0 のスプライトによるマスクは判定しない

## 試験

- 合成した VDP 状態で、スクロール、優先・反転・パレット、ウィンドウとの重なり、スプライトのリンク・表示判定・リンク終端、不正な範囲・プレーン名・Mode 4 を確認する
- fixture を止めた状態で、Plane A の 40×28 の grid、パターンの CRC、背景色レジスタ、フレーム番号を MCP から確認する
- 本体では、実行中の拒否、不正な params、既存ファイルの拒否、ファイルの大きさとレジスタ値、取得後もフレームが進まないことを確認する
